# Квиз по модулю "Ограниченные контексты (Bounded Contexts)"

## Вопросы

1.  Что такое Ограниченный контекст (Bounded Context) в DDD?
    *   **A)** Физическая граница между различными серверами в распределенной системе.
    *   **B)** Явно определенная граница, внутри которой определенная модель Ubiquitous Language применяется последовательно и без противоречий.
    *   **C)** Граница между различными модулями в коде, определяемая архитектурой приложения.
    *   **D)** Граница между различными базами данных в системе.

2.  Почему важно четко определять границы контекстов?
    *   **A)** Чтобы избежать конфликтов имен в коде.
    *   **B)** Чтобы предотвратить смешение различных моделей и языков, что может привести к путанице и ошибкам в понимании домена.
    *   **C)** Чтобы упростить развертывание приложения на разных серверах.
    *   **D)** Чтобы обеспечить совместимость с различными базами данных.

3.  Что такое Ubiquitous Language в контексте Bounded Context?
    *   **A)** Язык программирования, используемый во всем проекте.
    *   **B)** Общий язык, который используется как разработчиками, так и экспертами предметной области для описания концепций и процессов в рамках конкретного контекста.
    *   **C)** Язык документации, используемый для описания архитектуры системы.
    *   **D)** Язык запросов к базе данных.

4.  Какие типы отношений могут существовать между Bounded Contexts?
    *   **A)** Только иерархические отношения (родитель-потомок).
    *   **B)** Только независимые контексты без связей.
    *   **C)** Различные типы отношений: Customer-Supplier, Conformist, Anticorruption Layer, Open Host Service, Published Language и другие.
    *   **D)** Только отношения через общие интерфейсы.

5.  Что такое Context Map в DDD?
    *   **A)** Карта базы данных, показывающая связи между таблицами.
    *   **B)** Документ, который показывает границы и отношения между различными Bounded Contexts в системе.
    *   **C)** Карта архитектуры приложения, показывающая расположение компонентов.
    *   **D)** Карта развертывания системы на серверах.

6.  Что такое Shared Kernel в контексте Bounded Contexts?
    *   **A)** Общий код, который используется всеми контекстами.
    *   **B)** Небольшая модель, которая является общей для нескольких контекстов и управляется совместно.
    *   **C)** Общая база данных для всех контекстов.
    *   **D)** Общий интерфейс для взаимодействия между контекстами.

7.  Какая стратегия используется, когда один контекст должен адаптироваться к модели другого контекста?
    *   **A)** Anticorruption Layer (Слой защиты от коррупции).
    *   **B)** Conformist (Конформист).
    *   **C)** Customer-Supplier (Заказчик-Поставщик).
    *   **D)** Open Host Service (Открытый хост-сервис).

8.  Что такое Published Language в контексте интеграции между Bounded Contexts?
    *   **A)** Язык программирования, используемый для публикации API.
    *   **B)** Документированный язык или формат, который используется для обмена информацией между контекстами.
    *   **C)** Язык документации проекта.
    *   **D)** Язык спецификации API.

9.  Почему важно избегать "Big Ball of Mud" в контексте Bounded Contexts?
    *   **A)** Чтобы код был более читаемым.
    *   **B)** Чтобы избежать ситуации, когда границы контекстов размываются, и различные модели смешиваются, что приводит к сложности и непредсказуемости системы.
    *   **C)** Чтобы упростить тестирование.
    *   **D)** Чтобы улучшить производительность.

10. Как следует обрабатывать концепции, которые пересекают границы контекстов?
    *   **A)** Создавать общие модели для всех контекстов.
    *   **B)** Использовать переводчики (translators) или адаптеры для преобразования между различными представлениями концепций в разных контекстах.
    *   **C)** Избегать таких концепций полностью.
    *   **D)** Создавать единую глобальную модель.
